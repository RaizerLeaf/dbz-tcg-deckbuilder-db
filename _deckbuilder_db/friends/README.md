# Friends: deck building with a free chat AI

Plan and reasoning: `PLAN.md`. Phase 1 (pack + checker, command line) and Phase 2 (the static web page) are built. PanZ era (Sets 1-7) only; FanZ is a later TODO.

## The web page (Phase 2)
`docs/` at the repository root is a static site (plain HTML/JS/CSS, no server, no AI): pick an MP and styles, copy or download the pack, paste the AI's list to check it and get the deck
code, and browse cards. It is generated by `python friends/build_site.py` from the same data as the Python tools, and `core.js` is tested against the Python checker
(`friends/tests/test_site.py`, needs Node). **`docs/` is generated; never edit it by hand.** It is the only folder outside `_deckbuilder_db/`, because GitHub Pages can only publish the root or `/docs`.

**Turn it on (once, in GitHub):** merge this branch to `main`, then repository Settings -> Pages -> Build and deployment -> Source: *Deploy from a branch* -> Branch `main`, folder `/docs` -> Save.
The page appears at `https://<your-user>.github.io/<repo-name>/` after a minute or so. For local testing: `cd docs && python3 -m http.server 8000` and open http://localhost:8000.

**Keeping it current:** after any change to `cards.json` or `friends/site/` or `INSTRUCTIONS.md`, run `python friends/build_site.py` (from `_deckbuilder_db/`) and commit `docs/`.
The test `Fresh.test_docs_match_the_sources` fails if you forget. (An automatic GitHub Action could do this; it would live in `.github/`, outside `_deckbuilder_db/`, so it needs the owner's OK.)

## For a friend (any chat AI: Claude, Gemini, ChatGPT)
1. Get `dist/deckbuilder_pack.md` (full, about 70,000 tokens) or a lighter pack made for your MP (about 25,000-30,000 tokens, see below).
2. Start a new chat, upload the file (or paste it) and say: *"Follow the instructions at the top of this file. I want to build a deck for <MP>."*
3. The AI compares styles and builds a list in the format shown at the top of the pack.
4. Paste the list into the checker (below), fix whatever it reports, and copy the deck code into the deck-builder web app.
Free plans may limit file size, uploads, messages or context: if the full pack is refused, use a light pack.

## For the owner / anyone with Claude Code
```
python friends/build_site.py                                  # rebuild the web page (docs/) from the database
python friends/build_pack.py                                  # full pack -> friends/dist/
python friends/build_pack.py --mp Trunks --styles Red Orange  # light pack for one MP and the styles worth comparing
python friends/list_to_code.py deck.txt               # deck list from the AI -> deck code + legality check (needs scripts/deckcode.py)
python -m unittest discover -s friends/tests -t .             # tests
```
Run these from `_deckbuilder_db/`. Regenerate `dist/` whenever `cards.json` changes. The checker is the same legality code the owner uses (`scripts/deckcode.py`): 60 cards, copy limits, printed limits, Named cards,
Heroes/Villains only, Mastery-only cards, Allies, Dragon Ball sets, heritage lists, plus warnings for the owner's defaults. It does **not** judge strategy.

## Pack contents
`INSTRUCTIONS.md` (rules, legality, how to compare styles, output format) + MPs with every legal level printing + Masteries + cards by style (Black, Blue, Namekian, Orange, Red, Saiyan) + Freestyle
(including Allies and Dragon Balls). Each card appears once, with its current (errata-applied) text. Card images are not included.

## Known limits
- The AI can still misjudge strategy or miscount; the checker catches rule errors, not weak decks.
- MP names with an app qualifier (for example `Trunks (Awakening)`) must be written as the app shows them on the `MP:` line.
- Phase 3 (simulator in the browser) is not built.
